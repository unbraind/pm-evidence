# pm-evidence architecture

Evidence is external context used to justify a native item. This package checks exact bytes, not semantic truth. It has no model, network adapter, daemon, git invocation or hosted service.

## Descriptor and selectors

A descriptor contains `provider`, root-relative `source`, SHA-256 UTF-8 content `revision`, `selector` and an exact text `anchor`. The caller supplies the root each time; roots and resolved filesystem paths are never persisted or returned. The digest covers the entire coherent source snapshot. A git blob identity is optional in the proposal; this implementation always uses content digests, so there is no git dependency.

Line ranges are one-based, inclusive, with the cited quote and up to 24 neighboring characters on each side. Newline bytes within the fragment are significant. The line terminator after the final selected line is outside the fragment. UTF-8 BOMs are preserved; malformed UTF-8 refuses. Markdown supports ATX headings and blank-line-separated paragraphs; CLI selects the first paragraph, the SDK can select a one-based paragraph ordinal. It is not a complete Markdown parser. JSON pointers implement RFC 6901 (`~0`, `~1`), strict array indexes and own properties. JSON selection validates the entire document with a bounded, lossless value-span parser, then hashes the exact UTF-8 bytes of the selected value. Number lexemes are never converted to IEEE-754 doubles: 9007199254740992 and 9007199254740993 remain different. Internal whitespace, string escape spelling, numeric spelling and object member order remain significant; whitespace outside the selected value does not affect freshness. Duplicate decoded object keys are ambiguous, and more than 256 nested containers refuse. New pointer descriptors carry jsonEncoding: source-bytes-v1. Legacy descriptors without that exact marker require explicit re-anchoring after a source revision change; prior lossy digests are never silently upgraded.

Resolution first counts every exact quote occurrence, including overlaps. One exact quote is accepted only when both saved immediate surroundings match at its current location. Quote text alone never establishes passage identity. Heading anchors additionally store and match the full ATX section ancestry, so an unchanged example cannot replace a changed policy paragraph. Legacy heading records without section ancestry can be accepted only at their unchanged whole-source revision; source changes require explicit re-anchoring. Multiple hits are ambiguous even at the original line. There is no fuzzy matching. If the quote is absent, uniquely matching exact surrounding boundaries can identify a changed fragment. Empty boundaries mean the original file edge. Repeated boundaries are ambiguous; absent or reversed boundaries are missing. The original selector is never silently rewritten. Explicit re-anchoring follows the uniquely resolved current fragment, or uses a caller-provided replacement selector, and creates a separate citation from one coherent current snapshot while retaining the original and its reviews. A heading citation keeps its saved section scope across re-anchoring even when its new structural locator is a line range.

## Two axes

Resolution: `resolved`, `missing`, `inaccessible`, `ambiguous`, `unsupported`.
Freshness: `current`, `changed`, `unknown`.

Freshness compares selected fragment digests, independently of the source digest. An outside edit or movement that preserves the saved quote, surroundings and section ancestry is resolved/current with `sourceChanged: true`. Movement that changes the saved passage context requires review even when the quote survives. Ambiguous or unavailable current fragments have unknown freshness. `check({revision:'cited'})` verifies retained original bytes: resolution can be resolved while freshness is changed against the current fragment. `currentResolution` preserves current availability even during historical replay. Without retained bytes, historical resolution is missing. A caller cannot reconstruct original evidence from today's bytes. Ordinary checks do not automatically fall back to historical bytes.

## Native storage and writes

One registered optional string field, `evidence_state`, contains version 1, an evidence revision counter and citations. Native items, relationships, comments, settings and append-only history remain SDK-owned. This is a package field, not a competing core metadata reference or entry-ID schema. A citation includes fragment digest, descriptor, item/author/time provenance, observations, optional base64 retained fragment and compact last check. Citation IDs are deterministic fingerprints of item, descriptor and digest. Review IDs fingerprint citation, author, disposition, reason and replacement. Identical retries deduplicate; distinct reviewers remain distinct.

`citation-schema.ts` is the sole runtime citation/selector/ancestry shape and the source of their inferred TypeScript contracts. Producers validate before recording and readers use the same schema. Source strings remain literal, with source-size bounds; ancestry is not an identifier and can contain tabs and long Unicode headings. Envelope parsing is separate from entry parsing so one malformed citation cannot quarantine its siblings. Verification reports each malformed entry with its position and a typed remedy. Observation recording shares the existing SDK CAS/retry path, updates only valid entries, and preserves malformed entry data. A foreign outer envelope still refuses as an item-level boundary.

Schema registration goes through the SDK. Attribution uses SDK `selectImportAuthor` with SDK settings. Changes use `commitItemMutations` with a lock-held field match on the exact previous evidence envelope. The first write matches native `updated_at`: SDK 2026.10.23 does not accept an absent field match. The successful transaction updates the field, links file/JSON identities through native SDK linked files and appends a compact native comment together. Linked paths are logical identities relative to the caller-selected source root, labeled with that convention; they never persist the machine root. Eight CAS attempts bound contention; explicit `expectedRevision` refuses stale callers. No package code writes tracker files directly. SDK transaction journals and locks are disposable runtime data.

`check` records a compact last observation by default. SDK callers can request `record:false`, and CLI callers `--read-only`, for read-only checks. Recording re-reads each target through the SDK and fences on both the numeric evidence revision and the exact evidence envelope captured before verification. A replay retaining the numeric counter still conflicts when its envelope changes. CAS retries recheck these expectations; they never apply frozen observations to a revised target. Transaction keys also include the native target timestamp so an older committed journal cannot suppress a new application after an envelope replay. Skipped recording reports an incomplete receipt with a typed remedy. Check does not change citation digests, descriptors or reviews. No command closes items or declares a Decision false.

The pinned SDK's atomic mutation API takes a tracker root rather than an injected remote client. This MVP is proven for filesystem trackers with and without git. Reads may reuse an active host client; remote backend mutation conformance is not claimed. A future backend-aware atomic SDK API is required before making that claim.

## Limits and completeness

Built-in file and JSON readers require Linux with accessible procfs descriptor links. They canonicalize the selected root and source, reject traversal/absolute identities and symlink escapes, require regular readable files, and use no-follow/nonblocking opens. Immediately after opening and again after reading, they read the kernel target of /proc/self/fd/<fd>, verify that target and its real path remain inside the canonical root, and compare the target stat device/inode with fstat of the opened descriptor. Discovery and post-read metadata must also agree (device, inode, size, mtime and ctime). A parent symlink swap cannot authorize an external descriptor even when the pathname is restored after post-read stat. The race acceptance fixture reproduces that precise swap/restore sequence using real directories, symlinks and no-git trackers. If the platform, procfs link or descriptor verification is unavailable, the read refuses; there is no path-only or weaker fallback mode. Other platforms need a trusted custom adapter offering equivalent guarantees. The threat model includes concurrent untrusted pathname/parent-directory replacement, while trusting the Linux kernel, the procfs mount and the caller-selected canonical root. This is not a sandbox against kernel compromise or a caller-authorized adapter that deliberately bypasses containment.

Default cap: 1 MiB/source and 5 seconds/read. SDK caps can increase to 16 MiB and 60 seconds. Reads are bounded in memory and check cancellation at read boundaries. Custom adapters receive the same root/cap/signal contract and must provide a coherent SHA-256 content revision; their side effects and source authorization are caller-owned. The deadline bounds returned work even if a custom adapter ignores cancellation. Source bytes are read internally to compute the content revision; only fragments requested with `diff` enter output.

Each check or affected invocation owns a provider/source promise map. The root, adapters and read limits are captured for that invocation; adapter results are copied into immutable snapshots. All selectors, including citations pinned to different older revisions, resolve against those same current bytes. Refusals are shared too. Provider keys are never conflated, and no snapshot persists between invocations. The map is bounded to 10,000 sources and 64 MiB of retained UTF-8 bytes. A strict boundary rejects sparse arrays, non-finite/out-of-domain limits and malformed citation operands before use. Foreign envelopes are skipped without being overwritten.

Cancellation races the source read even when a custom reader ignores its signal, clears the deadline/listener, and returns `canceled:true` with an explicit incomplete receipt. It cannot stop arbitrary caller-owned adapter side effects. Pending source verification does not publish observations. Cancellation during recording skips subsequent targets and reports any committed observations. `receipt.verification` includes guarded read-attempt counts, unique sources, checked citations, recording/skip/foreign counts and typed skip remedies; all counters are finite integers in 0–10,000. Counters enter the same final-envelope budget calculation as rows, so withholding rows never hides source work or incompleteness.

The default check/affected budget is 800 estimated tokens. The estimate is the larger rendered host TOON/pretty JSON byte count divided by four, rounded up, including the omission receipt and its own counter. It is not a model tokenizer. Oversized packets keep a deterministic prefix and exact omitted row count. A budget too small for the receipt refuses. Source checks still cover the selected scope when output rows are omitted.

Affected uses `listAllComplete` and `certifyCompleteListResult`; incomplete corpus reads refuse. SDK `RelationshipGraph` supplies hierarchy and dependency paths. A projection reverses hierarchy edges so parents and incoming dependents share one traversal. Changed and unresolved evidence both require explicit review; current evidence does not. Paths are bounded by depth (default 2, maximum 16) and traversal limit (default 100, maximum 10000) per citation. `sourceComplete:false` and `complete:false` disclose unknown evidence or unexpanded graph frontiers. `omitted` counts enumerated rows withheld by the output budget; nodes beyond a traversal bound have unknown counts and are not included in that number. `scope` records item/citation denominators and requested traversal bounds. The result never claims global exhaustive impact from a partial source or traversal.

## Privacy and inert rendering

Only explicit `--retain` stores replay bytes. Text selectors necessarily store their exact quote/context to relocate evidence even without retention; retained replay is a separate verified copy. Source anchors and retained bytes are excluded from routine show/check output. `--diff` contains labeled `source-data` arrays; control bytes are escaped so ANSI cannot alter terminal output. Source content never becomes a command, callback, instruction, exception message or automatic upload. Diagnostics are package-owned text with remedies. Hashes and relative identities can still reveal equality and filenames; choosing sources and committing tracker evidence remains an explicit caller decision.
